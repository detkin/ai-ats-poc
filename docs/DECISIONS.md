# Decisions log

Deviations from `docs/SPEC.md` v0.2 mechanics, and choices the spec left open. Spec claims (§1) always win.

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-09-02 | No build step: Node 24 native type stripping; `bin/*.mjs` import `#lib/**/*.ts` directly; `tsx` kept only as a dev convenience. `tsconfig` uses `erasableSyntaxOnly` (no `enum`). | Spec §11 says "no build step for the demo"; verified working on Node 24.5. |
| D2 | 2026-09-02 | Imports use package subpath aliases (`#lib/...`) — never relative. Enforced by ESLint. | House rule (global CLAUDE.md). |
| D3 | 2026-09-02 | Tenant policy is machine-readable YAML at `tenant/policy.yml`; `modes/_tenant.md` is prose generated over it. Doctor's "template policy" check reads `template: true` in the YAML. | Spec §5: "policy is data, not prompt". A markdown-only `_tenant.md` would make the engine parse prose. |
| D4 | 2026-09-02 | Runtime Tier-2/3 state on fixtures lives in `TL_DATA_DIR` (default `./data`, gitignored) as JSON arrays + `ledger.jsonl`; `fixtures/tenant/` is read-only seed. | Tick mutates state; tests need fresh copies; fixtures must stay reproducible. |
| D5 | 2026-09-02 | Fixture tenant has 3 OPEN reqs (spec) plus one CLOSED historical req so rediscovery (M4) has silver medalists ~4 months old. | Spec §8 loop-4 demo needs them; adding later would churn the manifest. |
| D6 | 2026-09-02 | Commit messages end with the `Co-Authored-By: Claude Fable 5.1` trailer per the project mandate, overriding the global commit-message skill's "no co-author" rule. | Project CLAUDE.md is more specific. |
| D7 | 2026-09-02 | Nudge text is templated with injected facts (no LLM call on the tick path in the POC). LLM use is reserved for packet summaries and is marked `derived`. | Spec §7 "LLM use is narrow"; keeps ticks deterministic and evals cheap. |
| D8 | 2026-09-02 | Frozen clock via `TL_NOW`; fixtures anchored at `2026-09-02T16:00:00Z`. | Idempotence and golden tests need a fixed "now". |
| D9 | 2026-09-02 | The seeded review cycle `tl_cycle_h2_2026` ships with `status: configured` and `opened_at: null`. `cycle.mjs open` sets `opened_at` (the plan's 2026-08-24 was the intended open date, not a seeded value) and creates the tasks. | Opening is a ledgered write and belongs to the CLI, not the fixture. |
| D10 | 2026-09-02 | Spec §6 reference columns are implemented with explicit suffixes: `cycle_id`, `owner_worker_id`, `participant_worker_id`. Exception: `TlProposedAction.decided_by` keeps the spec's name (it pairs with `decided_at`). | Consistent with the ledger's `cycle_id`; removes ambiguity between an id and an embedded value. |
| D11 | 2026-09-02 | `bin/*.mjs` must be thin: arg parsing + one `lib/cli/*.ts` call + rendering. `bin/seed.mjs` violates this today (tester defect D-1/D-2); B1.3 moves its logic to `lib/cli/seed.ts` and uses `loadConfig()`. | Logic in a CLI is untestable except by subprocess, and eight more CLIs arrive in M1. |
| D12 | 2026-09-02 | Moved due date = (absence `until` + 1 day, the return day) + `absence.move_due_date_days_after_return`, at 23:59:59Z. `until` is the inclusive last day of the absence. | Policy text says "days after return"; the first engine cut counted from the last absent day. |
| D13 | 2026-09-02 | `tick.mjs --scan <doc_ref>` screens an untrusted document through `ats.readDocument` and records a `tl_anomaly` if it contains instruction text. Review bodies are screened automatically; résumés only on request, since loop 1 never reads one. | Gives the safety rule a demonstrable path in M1 without inventing a résumé read the review cycle would never do. |
| D14 | 2026-09-02 | `nudge.mjs --force-policy-check` prints the policy gate and never sends. There is no bypass flag for "no nudge on absence". | Spec §4 rule: Rippling absence wins; a bypass would make the demo's central promise conditional. |
| D15 | 2026-09-02 | Last-tick bookkeeping lives at `<TL_DATA_DIR>/ticks/<cycle_id>.json`, outside `state/`, not a `tl_*` object and not ledgered. | It is a cache of the previous plan, not engine state; storing it on `tl_cycle` would put a derived value on a record. |
| D16 | 2026-09-02 | The escalation sends exactly one DM to the recipient after creating the proposal; the open proposal's `evidence_refs` prevent a second one. | Spec §8: the HRBP "sees one escalation with evidence instead of forty reminders". |
| D17 | 2026-09-02 | Nudges are batched per recipient per tick: one DM listing every overdue task, one `tl_nudge` record per task sharing the DM's `message_ref`, and `cadence.nudge_min_gap_hours` measured per recipient. | M1 tester: per-task fan-out sent 253 DMs to 86 people on one tick (up to 4 each). One reminder per person is the spec's promise. |
| D18 | 2026-09-02 | Quiet hours are per location, so a single-instant tick reaches only locations inside working hours (16:00Z = SF morning, Bangalore night). The demo runs a second daily tick at 06:00Z for India; a real deployment schedules ticks per location. | Policy behaving correctly; the walkthrough had assumed one instant fits everyone. |
| D19 | 2026-09-02 | Every CLI that acts on a record (`decide --proposal`, `nudge --task`) resolves the record's `cycle_id` before opening the ledgered runtime, so its ledger lines carry the cycle. | M1 tester: the HRBP's approval was invisible to `audit --cycle`. |
| D20 | 2026-09-02 | A public holiday is quiet (no nudge that day) but never moves a due date; only approved leave (`source: rippling.absence`) triggers `move_due_date`. | The fixer observed Labor Day shifting 349 US deadlines by two days. A holiday is not a reason a person cannot finish their review by the deadline. |
| D21 | 2026-09-02 | Interview scheduling window is `now + 5 days` to `now + 26 days`, 60-minute slots, earliest first. | Five days' notice is the tenant convention; the engine's "≥ 2 business days" preference alone would book the fixture panel two days out. |
| D22 | 2026-09-02 | A Slack reply becomes a fact only through explicit metadata: `message_ref` `scorecard_<worker>` is a scorecard body; anything else is screened for a decline with a narrow regex. Bodies are untrusted and screened for instruction text. The Channel port should grow an `author` field before a real Slack adapter exists (Q7). | The fixture channel returns `UntrustedDocument` without an author; inferring the author from free text would be an injection vector. |
| D23 | 2026-09-02 | `attend_interview` tasks are never nudged; attendance completes by observation once the slot has ended. A rebook re-keys the decliner's pending scorecard to the substitute. A worker who declined a slot is excluded from substitution for that slot. | B2.2 found the generic nudge rule chasing attendance after the interview, the reference executor leaving the scorecard on the decliner, and the substitute picker re-selecting a decliner. |
| D24 | 2026-09-02 | Multiple `rebook` actions in one tick compose: the executor carries live slot/scorecard maps and each rebook reads the slot's current panel. `verify-loops` rule `interview_panel_reconciles` checks that a slot's panel equals the workers holding its tasks and scorecards. The `advance_stage` proposal cites the debrief packet id. | M2 tester: a second decline re-booked the first decliner and two rebooks clobbered each other while verify-loops passed. Capping the planner to one rebook per tick would have left the reference fold and the executor disagreeing. |
| D25 | 2026-09-02 | The Rippling MCP is agent-executed, not script-executed: the OAuth token lives in the Claude client, so `bin/*.mjs` cannot call `codemode.*`. The rippling path becomes a bridge — the agent fetches/writes via the `code` tool per the mode file and hands JSON to scripts; REST (customer token) is the only script-executed Rippling path. | Live smoke: the MCP tool is only visible to the model. Spec §5 "LLM plans, scripts enforce" still holds: scripts validate and ledger what the agent fetched. |
| D26 | 2026-09-02 | Every `codemode.*` call carries `telemetry: { intent }`; records created in custom objects carry a mandatory `name` and use `external_id` for the `tl_*` id. | Gateway contract observed live. |
| D27 | 2026-09-02 | Quiet hours derive from the worker's timezone plus tenant default work hours; locations carry no hours. Absence is present-tense from the MCP; dated absences (for due-date moves and scheduling) come from REST leave requests when available, else the engine treats `current_leave.end` as `until`. | Live smoke: location has no timezone/hours; `lookup_absence` returns `is_on_leave` only. |
